# Static infrastructure — Dams

## What this is

The `dams.geojson` in this folder is the seed data for the
`static_infrastructure` Postgres table (kind = `dams`). It is consumed by
`ingestion/load_static_infrastructure.py`, exposed via
`GET /api/infrastructure?kind=dams&bbox=...`, and rendered as a Mapbox
`fill` + `line` layer in `src/components/Map/BorderMap.tsx`.

## What's NOT in this file

- The Mekong-subregion focus that the geopolitics dashboard wants is
  achieved by the **bbox filter** on `/api/infrastructure`, not by trimming
  the source. The full 704-feature global set is loaded once; the API only
  returns the bbox slice the map is showing. ~40 features are relevant to
  the Thailand–Cambodia–Myanmar–Laos border theatres.

- The GEV bundle strips contact-oriented tags (email, phone) and any note
  value containing an email or phone identifier. We ship the same file
  unchanged. The ODbL-derived database you build on top remains ODbL
  regardless.

## How to refresh

```bash
# 1. Pull a fresh copy
curl -sL --max-time 60 \
  "https://raw.githubusercontent.com/bilawalsidhu/gods-eye-view/main/src/data/local_data/dams/dams.geojson" \
  -o ingestion/data/static/dams.geojson

# 2. Re-load (idempotent on (kind, osm_id))
.venv-ingestion/bin/python ingestion/load_static_infrastructure.py --kind dams
```

## Refugee camps (kind: `refugee_camps`)

| Field | Value |
|---|---|
| Upstream | TBC Programme Report (Dec 2025) + UNHCR Operational Data Portal |
| Path | `refugee_camps.geojson` (generated by `ingestion/fetch_refugee_camps.py`) |
| License | **UNHCR: CC0** (public domain) · **TBC**: public, attribution required |
| Commercial use | ✅ Yes (UNHCR CC0 is unrestricted; TBC is publicly redistributable) |
| Attribution | "Data: UNHCR Operational Data Portal + The Border Consortium (TBC)" |
| Feature count | 9 (the 9 official Thai-Burma border refugee camps) |
| Population source | Live UNHCR Population API → corridor total → distributed by TBC's published Dec 2025 share |
| Refresh | `bash ingestion/run_safety_ingest.sh` (or just `python ingestion/fetch_refugee_camps.py` + loader call below) |

### What it shows on the map

A point for each of the 9 camps. Hover shows the camp name, province,
district, year established, operator (TBC), and the estimated
population from the most recent UNHCR corridor total × TBC share.
Click-through (when wired) will deep-link to the camp's UNHCR profile.

### Why the distribution is a *share* of the corridor total

UNHCR's population API returns the corridor-level total (Myanmar
refugees in Thailand) at country/ISO level, not per-camp. We
distribute it using TBC's published Dec 2025 per-camp shares
(https://www.theborderconsortium.org/). This gives realistic
per-camp numbers for an operator who pans to the Tak / Mae Hong Son
/ Kanchanaburi border strip, without claiming camp-level
granularity we can't actually verify.

### Refresh procedure

```bash
# Pull latest corridor total from UNHCR, redistribute via TBC shares
.venv-ingestion/bin/python ingestion/fetch_refugee_camps.py

# Load into Postgres (idempotent on (kind, osm_id))
.venv-ingestion/bin/python ingestion/load_static_infrastructure.py --kind refugee_camps
```

The `fetch_refugee_camps.py` script does *not* call any APIs that
require keys. UNHCR's population API is keyless; the TBC Dec 2025
share table is committed.
